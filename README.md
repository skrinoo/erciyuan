# こころのよりどころ · 心灵依靠 | 解压小游戏

一个二次元美少女解压小游戏：输入你的烦恼，选择不同性格的美少女（病娇 / 傲娇 / 温柔大姐姐），
她会用**日语语音 + 中文字幕 + 表情变化**回应你。

纯静态 HTML/CSS/JS，**无需安装 Node.js、无需构建**，双击 `index.html` 即可玩。

---

## 快速开始

1. 双击打开 `index.html`（推荐 Chrome / Edge）。
2. 底部选择性格 → 在输入框写下烦恼 → 点「倾诉 💬」（或 `Ctrl + Enter`）。
3. 美少女会切换表情、打出中文字幕、播放语音。

> 首次打开若浏览器拦截本地音频/语音，请点击地址栏允许即可。

## 语音方案（重要）

全部语音均为**女声**，并按性格匹配日漫典型声线（StepFun 官方音色）：

| 性格 | 音色 ID | 声线参考 |
|---|---|---|
| 病娇 · 绫音 | `tianmeinvsheng` | 甜美女声，可转病态执拗（类病娇役） |
| 傲娇 · 千夏 | `livelybreezy-female` | 活力高亢少女（类傲娇役） |
| 温柔大姐姐 · 美咲 | `wenroushunv` | 温柔熟女，包容母性（类大姐姐役） |

语音按以下优先级自动选择：

1. **远端 TTS**：设置里选「远端 TTS」并填 API Key → 实时调 StepFun 语音接口（带上述音色 + 角色语气指令）。
   台词里的全角括号演技指示（如 `（小声で）`）不会被朗读，只改变声音的表演。
2. **预生成女声音频（默认 Mock 模式即用）**：
   - 开场白：`assets/audio/<性格>/greeting.mp3`
   - 语料回复：`assets/audio/<性格>/c0.mp3 ~ c7.mp3`（对应 `mockCorpus.js` **前 8 条**）
   - 兜底句：`assets/audio/<性格>/f0.mp3 ~ f2.mp3`（对应 `MOCK_FALLBACK` **前 3 条**）
   离线即可播放真·日语女声。
3. **Web Speech 兜底**：没有预生成音频的条目（语料第 9 条起、兜底句第 4 条起）走浏览器 Web Speech；
   **系统无日语语音包、或日语台词为空**时改念中文字幕，保证始终有声。

> 音频覆盖上限由 `js/adapters.js` 的 `SR.MOCK_AUDIO_MAX = 8` 与 `SR.MOCK_FB_AUDIO_MAX = 3` 控制。
> **扩充语料时务必同步这两个常量**：超出磁盘上实际存在的音频数会静默 404 + 无声。

### 浏览器没声音？

自动播放策略会拦下首次音频播放。此时舞台顶部会出现 **🔈 开启声音** 按钮，
点一下即可在用户手势里重播当前台词（`SR.stats.autoplayBlocked` 会记录发生次数）。

### 想换音色 / 全实时日语？

- 改 `js/personalities.js` 里各性格的 `tts.voiceId`（StepFun 官方女声还有
  `qingchunshaonv` 清纯少女、`jingdiannvsheng` 经典女声、`elegantgentle-female` 高雅女声等）。
- 填 API Key 并选「远端 TTS」，则每条回复都实时合成日语女声。

## AI 后端（可插拔）

设置面板可切换：

- **Mock（默认）**：离线语料库，零成本、零依赖、永远可用。每角色 20 条话题语料 + 6 条兜底句，
  按**命中关键词打分**匹配（长词权重更高），取最高分、同分随机，并避免连续两次重复同一条。
  旧实现是“第一个命中即返回”，条目顺序决定结果，多意图输入必然答非所问。
- **StepFun / aiping.cn**：填 API Key 后接真模型实时生成回复（日语角色扮演）。
  调用失败会自动回退 Mock，游戏不中断。
  勾选「**API Key 仅本次会话有效**」可让 Key 不写入 localStorage（公用电脑场景）。

### 输出契约与补救链

真模型的系统提示词 = 角色 `systemPrompt`（`js/personalities.js`）+ 回复质量规则 + 对话记忆块
+ 长期记忆块 + 演技指示词表 + **输出格式契约**（恒在最末尾以保合规），要求严格三行：

```
[emotion:normal|smile|angry|sad|love]   ← 首行，JA 一流完就能带情绪并行合成语音
JA: <日语台词，可含最多 2 个全角括号演技指示>
ZH: <上一行的简体中文翻译，不含括号>
```

模型并不总是守约（实测**情绪越重、违约率越高**：JA 行整行写成中文、ZH 原样复制）。
前端不依赖模型自觉，而是逐层校验与补救：

| 违约形态 | 处理 | 计入诊断 |
|---|---|---|
| JA 行是中文 | 带角色人设回灌**重写**成日语（不丢口吻） | `jaViolation` / `jaRewrite` |
| 重写失败 | 退回中→日翻译 | `translateFix` |
| 只给日语漏中文 | 日→中翻译补齐 | `translateFix` |
| 括号指示不在角色白名单 | 直接剥离（防字幕噪音与 TTS 审核 451） | `cueStripped` |
| 两边都救不回 | 抛错回退 Mock，绝不给空白 + 无声 | `fallback` |

语言校验用 `SR._isJapanese`（含假名）/ `SR._isChinese`（含汉字且无假名）双向判定；
翻译彻底失败时**宁可留空也绝不把错误语言的文本填回字幕或语音**（防“双中文/中文语音”复发）。

> `step-3.7-flash` 是**思考型模型**：`reasoning_content` 同样消耗 `max_tokens`。
> 实测一句 40 字台词可吃掉 500~900 token，故对话用 `max_tokens: 2048`、翻译/重写用 `1024`
> （早先翻译写 200 会被思考耗尽 → 译文为空 → 静默失败）。

### 记忆

- **短期**：每次请求注入同角色最近 3 轮对话，并明令禁止复用旧句式（治“公式化回复”）。
- **长期**：同角色每满 10 轮（`SR.PROFILE_EVERY`，最少 4 轮），异步把历史压缩成
  「关于你的备忘」（3〜5 项、每项 25 字内、禁止推测），存 localStorage 并跨会话注入 prompt。
  异步、失败静默，不阻塞当前回复；生成时提示「XX 记住了更多关于你的事」。

### 版本自检

浏览器跑旧缓存 / 部署前就开着的旧标签页，是“已修复 bug 复发”的历史根因，而旧代码无法被远端修复。
故 `index.html` 带 no-store meta、所有本地资源带 `?v=`，`SR.BUILD` 为构建戳；
启动时与每 5 分钟用 `cache:'no-store'` 拉一次同目录 `index.html`，比对 `main.js?v=` 与 `SR.BUILD`，
过旧则提示并自动刷新一次（sessionStorage 60s 防循环）。

> 本地开发时若把 `SR.BUILD` 升版但尚未部署，**不会**触发刷新——比对的是相对路径的同目录 `index.html`。

## 对话历史

顶栏 📜 打开历史面板，每条记录包含：你的烦恼、她的中文字幕、情绪标签、时间（今天/昨天/M月D日 + HH:MM），
以及一个 **🔊 重播** 按钮——点击会同步切回当时的表情立绘与字幕，并重播同一条语音
（有预生成音频就用它，否则走当前语音引擎）。

- **角色筛选**：下拉可只看某个角色的对话（选项按 `SR.PERSONALITIES` 自动生成）。
- **导出**：存为 `kokoro-history-YYYY-MM-DD.json`（含原文、双语、情绪、时间戳），便于回顾或归档。
- **清空**：面板右上角。

## 运行诊断

设置面板底部的「运行诊断」把 `SR.stats` 的真实计数摆到眼前（存 localStorage，跳会话累计，可「清零」）：

| 指标 | 含义 |
|---|---|
| 真模型成功 / 回退 Mock | 真实可用率，以及静默降级发生了多少次 |
| 空响应 | 流式正文为空（思考耗尽 `max_tokens` / SSE 异常） |
| 审核 451 / TTS 失败 | 内容审核拦截与其他语音合成失败 |
| JA 行违约 / 重写救回 / 翻译补齐 | 模型不守双语契约的频率与补救成效 |
| 剥离越界 cue | 被白名单拦下的自创演技指示数 |
| 播放被拦 | 自动播放策略拦下音频的次数 |
| 首响均值 / 首响最近 | 流式首 token 耗时（思考型模型的“空等”到底多久） |
| 最近错误 | 最后一条失败原文（含 HTTP 状态与服务端 error.message） |

控制台也可随时 `SR.stats.dump()` 拿到完整对象。

## 扩展指南

- **加新性格**：在 `js/personalities.js` 加一项；在 `assets/characters/<id>/` 放 5 张表情图；
  在 `js/mockCorpus.js` 加语料；在 `styles/themes.css` 加主题色；在 `index.html` 无需改动
  （切换按钮与历史筛选下拉均自动生成）。
- **加新表情**：在 `config.js` 的 `EMOTIONS` / `EMOTION_LABELS` 加项，并放同名图片。
- **调语料**：直接编辑 `js/mockCorpus.js`。关键词越具体越好（打分按词长加权，单字词权重最低）；
  新增条目超出前 8 条就没预生成音频，会自动走 Web Speech，无需改代码。
- **改演技指示**：角色 `tts.cues` 就是白名单，不在其中的括号指示会被 `SR._normalizeCues` 剥掉。
  切勿加密着/性暗示类词（如「甘くささやく」），实测必触发 TTS 审核 HTTP 451。
- **改完记得升版**：同步修改 `index.html` 里全部 `?v=` 与 `config.js` 的 `SR.BUILD`，否则客户端会继续跑旧缓存。

## 已知限制

- Web Speech 兜底的日语音色取决于操作系统；未装日语语音包时念中文字幕。主回复与开场白均为预生成日语女声，不受影响。
- 真模型 / 远端 TTS 需要自备 API Key；女声音色 ID 已在 `personalities.js` 配好，可自行替换。
- `step-3.7-flash` 是思考型模型，首 token 前有一段“空等”（实测数秒）；设置面板的「首响均值/最近」可量化它。
- 真模型偶尔不守双语契约（情绪重的输入下更明显），前端会重写/翻译补救；
  极少数两边都救不回时，会只给中文字幕并用浏览器语音念中文（不会无声）。
- 长期记忆需要真模型（离线 Mock 无 Key 不生成），且只存本机 localStorage，换浏览器/清缓存即丢。
- **未做移动端适配**：布局无 media query，用 `100vh` 而非 `100dvh`，小屏体验不佳。
- **首屏约 6.9MB**（三张立绘各 1.0~1.3MB），未做懒加载/压缩，弱网下首次打开偏慢。
- **无危机干预**：输入自伤/自杀类内容时，角色仍按人设回复，未接入求助热线引导。
- `file://` 协议下个别浏览器对 localStorage 支持有限；如遇设置不保存，可改用本地服务器（如 `python -m http.server`）打开。
